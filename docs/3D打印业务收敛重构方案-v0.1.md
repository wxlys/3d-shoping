# 3D 打印业务收敛重构方案 v0.1

| 项目 | 内容 |
|---|---|
| 日期 | 2026-09-04 |
| 依据 | `3D打印服务系统-PRD-v0.1.md`、`改版清单-v0.1.md`、当前源码与服务器菜单 |
| 目标 | 将通用 CRMEB 商城收敛为“定制 3D 打印 + 3D 打印成品 + 秒杀成品”的专用业务系统 |
| 当前阶段 | R0 范围审计完成，尚未执行大面积删除 |

## 1. 重构原则

1. 已跑通的“询价 → 报价 → 转订单 → mock 支付 → 排单 → 打印 → 自提 → 待评价”是最高优先级保护链路。
2. 与 3D 打印业务直接相关的功能保留并改造；能提升购买、售后、内容说明和运营效率的能力精简保留；完全无关的能力移除。
3. “移除”不能只隐藏菜单：应同时处理页面入口、路由、接口权限、后台菜单、配置项和消息触发，避免旧地址仍可访问；但凡被后续节点依赖的底层能力不得提前删除。
4. 不直接删除订单、商品、用户共用字段。CRMEB 原有订单服务大量读取优惠、积分、会员、佣金字段，第一阶段保留字段并固定为零，待依赖清除后再决定是否删表或删字段。
5. 每个重构节点独立提交 Git、部署和验证；出现问题可以按节点回退。
6. H5 继续由用户使用 HBuilderX 构建；源码节点完成后再统一构建，不在每个小改动后重复构建。

## 2. 目标业务结构

### 2.1 用户看到的核心业务

- 定制打印：上传模型、选择尺寸/材料/数量、询价、确认报价、支付、排单、打印、自提。
- 成品商城：购买已经打印好的成品，支持购物车、快递、商家配送和到店自取。
- 限时秒杀：成品商品参加 CRMEB 现有秒杀活动，不作为第三种商品业务类型。
- 订单与售后：订单查询、退款、确认收货、评价、站内消息。
- 辅助内容：打印须知、材料说明、尺寸指南、取件说明、常见问题和联系客服。

### 2.2 首页与导航建议

首页一级业务入口固定为：

1. 定制打印
2. 热门成品
3. 限时秒杀
4. 打印指南

“热门”“新品”“推荐”属于运营集合或标签，不作为商品分类。这样同一商品可以同时属于“工具配件”和“热门推荐”，避免分类结构被运营状态污染。

### 2.3 商品分类建议

| 一级分类 | 二级分类示例 | 定位 |
|---|---|---|
| 家居生活 | 收纳整理、厨卫用品、家居装饰 | 家庭使用的打印成品 |
| 玩具与游戏 | 益智玩具、桌游配件、模型玩具 | 娱乐和亲子场景 |
| 工具与配件 | 夹具支架、维修辅助、数码配件 | 实用工具及替换件 |
| 模型与摆件 | 建筑模型、角色摆件、展示模型 | 收藏、展示和模型制作 |
| 创意礼品 | 个性礼物、纪念品、定制装饰 | 礼赠与个性化成品 |

定制打印不是普通商品分类，而是独立业务入口；后台仍可用一个“定制打印服务”商品承载询价入口。服务器商品数据目前为零，因此正式分类调整不会产生旧商品迁移问题。

商品分类保持后台动态管理，不写死在前端。管理员可在“商品中心 → 商品分类”新增、编辑、删除、排序、启用/停用分类，再通过“内容运营 → 页面装修”决定首页展示哪些分类及其顺序、图片和样式。上述分类只是建议初始化值，后续可自行调整。

服务器当前仍有 35 条“手机数码、电脑办公、日常用品”等原商城演示分类，以及引用旧演示商品的装修模板。R1 将备份后替换这些演示数据，并建立一套可继续编辑的 3D 打印默认分类/首页模板；不会删除分类管理和装修能力。

## 3. 管理后台模块取舍

目标后台由当前 13 个一级模块收敛为 9 个业务入口：

1. 工作台
2. 打印业务（询价、排单、打印设备与参数）
3. 订单中心（订单、售后、核销）
4. 商品中心（商品、分类、规格、参数、标签、评论、秒杀）
5. 用户中心（用户、分组、标签）
6. 内容运营（打印指南、首页/分类/个人中心装修、素材）
7. 客服
8. 财务
9. 系统（发货/自提、消息、协议、App 配置、权限、日志、安全与数据维护）

营销不再作为一级模块，仅将秒杀并入商品中心；分销和应用一级模块取消，App 基础配置并入系统。

### 3.1 保留并围绕业务改造

| 模块 | 保留内容 | 重构方向 |
|---|---|---|
| 主页 | 工作台 | 改为询价待处理、打印队列、待取、退款、库存预警、今日订单/成交额 |
| 用户 | 用户管理、分组、标签 | 删除会员、积分、分销、充值维度；突出订单、询价、文件和售后记录 |
| 订单 | 订单、售后、询价、排单、核销、订单配置 | 统一定制与普通订单状态文案，去掉收银台和无关营销订单筛选 |
| 商品 | 商品、分类、规格、参数、标签、评论、库存配置 | 只保留成品/定制两种业务类型；去掉会员价、佣金、优惠券、虚拟商品、预售、卡密等字段和操作 |
| 秒杀 | 秒杀管理 | 作为唯一保留的营销活动，限定只能选择成品商品 |
| 财务 | 订单流水、退款收支 | 去掉佣金、提现、充值和余额运营功能 |
| 内容 | 文章、文章分类 | 用于打印指南、材料说明、取件说明、常见问题，可适当简化编辑能力 |
| 装修 | 首页、分类页、个人中心、主题、素材、链接、自定义页面 | 保留完整的通用装修骨架，预置 3D 打印业务入口；只移除依赖优惠券/拼团/砍价等已下线业务的数据组件 |
| 客服 | 用户留言、基础客服 | 作为询价前咨询和售后补充；去掉依赖公众号生态的自动回复能力 |
| 设置 | 系统、协议、站内消息、发货、自提点、权限、操作日志 | 增加打印配置，移除小票、外部支付及不用的第三方配置 |
| 维护 | 安全、数据维护、系统信息 | 仅超级管理员可见；生产环境隐藏开发工具、路由生成和在线升级入口 |
| APP | App 基础配置 | 保留到后续 App 构建阶段使用 |

### 3.2 从业务界面和可访问路由移除

| 原模块 | 处理结论 | 原因 |
|---|---|---|
| 优惠券、新人礼 | 移除 | PRD 明确不使用，会干扰定制报价和订单金额口径 |
| 积分、签到、积分商城 | 移除 | 与当前支付及定价模型无关 |
| 砍价、拼团、抽奖、渠道码 | 移除 | 与一期 3D 打印业务无关，保留会扩大状态机和测试范围 |
| 分销、推广员、佣金、提现 | 移除 | 无分销业务，并污染用户、商品、订单和财务页面 |
| 付费会员、会员价、用户等级权益 | 移除 | 当前无会员价格体系 |
| 用户充值、余额运营 | 移除 | 一期使用 mock 支付，不做储值业务 |
| 直播 | 移除 | 与打印服务无关，且依赖微信生态 |
| 公众号、小程序、PC 独立端 | 移除后台入口，首轮保留共享适配代码 | 当前交付端为 H5、App 和管理后台；平台条件代码可能与通用登录/分享共用，须在 App 构建验证后才能物理删除 |
| 收银订单、线下收银 | 移除 | 不属于当前订单来源 |
| 小票打印 | 移除 | 当前没有门店收银硬件需求 |
| 预售、虚拟商品、卡密、自动发货 | 移除 | 当前只存在实体成品和定制打印 |
| 好友代付 | 移除 | mock 支付流程不需要代付关系 |
| 优惠券/拼团/砍价等专属营销专题组件 | 移除 | 不保留已下线营销业务的数据源和跳转 |
| 通用自定义页面（微页面） | 保留并改名 | 用于打印指南、材料说明、活动介绍和首页装修，是业务自定义能力的一部分 |
| 多语言设置 | 暂时移除入口、保留底层 | 一期仅中文；底层直接删除风险较高 |

### 3.3 数据兼容策略

- 保留订单表中的 `coupon_price`、`deduction_price`、`use_integral`、会员优惠、佣金等共用字段，但所有新订单固定为 0，前后台不再展示或允许编辑。
- 保留用户表中的余额、积分、推广关系等历史字段，接口不再提供业务入口；待核心服务完成解耦后再评估物理删除。
- 独立业务表（砍价、拼团、分销、签到、付费会员等）先停止写入并断开路由，经过完整回归后再决定是否删除表。
- 秒杀相关表、库存锁定和支付超时释放逻辑保留。
- 商品分类、标签与推荐位重新初始化；正式数据不沿用 CRMEB 的手机数码、办公用品等演示分类。

## 4. 用户端模块取舍

### 4.1 保留并优化

- 登录、注册、密码找回和退出。
- 首页、商品分类、搜索、商品列表和详情。
- 定制询价、我的询价、我的文件。
- 成品购物车、结算、mock 支付。
- 秒杀列表和秒杀详情。
- 普通订单、定制订单、退款、物流/自提、确认收货和评价。
- 普通配送订单的收货地址；定制打印不读取地址。
- 消息中心、个人资料、打印指南、常见问题和联系客服。
- 底部导航：首页、分类、购物车、我的。

### 4.2 删除入口、路由和页面注册

- 优惠券、积分中心、签到、积分商城。
- 砍价、拼团、抽奖、预售。
- 分销中心、推广人、佣金排行、提现。
- 充值、余额明细、付费会员、会员优惠券。
- 直播、渠道码、新人礼、专题营销页。
- 商家入驻、好友代付、虚拟商品/卡密页面。
- 微信公众号和小程序专属业务入口；共享登录、上传、分享和平台条件分支先保留，待 H5/App 都构建验证后再判断是否可删除。
- 用户端内嵌的移动管理后台页面首轮从普通用户入口隔离，但移动核销相关页面和接口保留到履约正式回归结束，避免截断后续核销场景。

当前 `pages.json` 约注册 130 个页面。上述无关页面不仅要从首页隐藏，还要从分包注册中移除，并清理对应 API 引用和跳转，减少 H5/App 包体及误入口。

## 5. 核心业务不得破坏的约束

1. 定制商品不能加入购物车或走普通商品直接购买。
2. 成品和秒杀不能进入打印询价或打印队列。
3. 同一模型仅在旧询价仍为待报价/已报价时阻止重复询价；询价任务完成后允许复用。
4. 预计交付时间只由后台报价和人工改期控制，不得恢复材料/体积自动估时覆盖。
5. 定制打印始终到店自提并使用 6 位取件码。
6. 普通下单自提使用 12 位核销码；后台改为到店自取时填写地点并进入待收货。
7. 确认收货或后台核销后必须进入待评价，评价完成或满 7 天才进入已完成。
8. 定制仅排队中且未开始打印可退款；普通成品/秒杀仅待发货或待核销可退款。
9. 订单金额、库存释放、退款和秒杀限购不能再受到优惠券、积分、会员或佣金逻辑影响。
10. 菜单不可见不等于无权限；移除模块的旧接口必须不可访问。

## 6. 后续节点兼容性复核

### 6.1 节点 H 依赖，重构期间必须保留

| 后续能力 | 必须保留的基础 |
|---|---|
| 异步文件校验 | 上传服务、文件记录表、任务/队列机制、文件大小/MIME/文件头配置、我的文件入口 |
| Web 根目录外存储 | 文件存储适配层、下载鉴权接口、素材管理与服务器存储配置 |
| 站内消息补齐 | 消息中心、系统通知表、定时任务、用户消息接口和后台消息配置 |
| 询价/评价/文件定时维护 | CRMEB 定时任务入口、服务器 Cron、打印维护任务、系统配置 |
| 菜单与 RBAC | 管理员、角色、菜单、接口权限、登录会话和操作日志 |

因此，消息管理、文件上传、定时任务、系统配置、权限、操作日志、Redis/队列等即使位于通用模块中，也不得随无关商城功能删除。

### 6.2 节点 I 依赖，重构期间必须保留

| 后续能力 | 必须保留的基础 |
|---|---|
| H5 与 App 共用 | uni-app 主工程、条件编译、通用登录、上传、路由、请求封装、App 配置 |
| 秒杀并发测试 | 秒杀活动、库存锁定、Redis、限购、支付超时释放 |
| 文件安全测试 | 上传鉴权、白名单校验、私有下载、操作日志 |
| 越权与接口测试 | 用户/管理员鉴权、RBAC、路由中间件、审计日志 |
| 发布与回退 | Git 节点、SQL 升级脚本、服务部署配置、数据库与 H5 备份机制 |

重构不能通过删除共享登录、请求、支付成功回调、库存、Redis、上传、通知或权限框架来缩小项目；只能清理其上层无关业务分支。

### 6.3 防截断措施

1. 每个删除候选先反查前端导入、路由、控制器、服务、定时任务和数据库外键/业务引用。
2. 对节点 H/I 依赖建立“保护清单”，保护项不得出现在批量删除脚本中。
3. 页面移除前先将核心跳转改到新入口；接口停用前先确认没有保留页面调用。
4. H5/App 共用代码在 App 尚未构建前原则上不物理删除，只允许关闭明确的业务入口。
5. 后台装修组件采用白名单保留：导航、轮播图、商品列表、商品分类、文章、图片、视频、搜索、自定义页面、定制打印入口和秒杀入口。
6. 每个 R 节点结束后至少执行定制、成品、秒杀三条链路的静态依赖检查；正式业务测试仍由后续测试阶段统一开展。

## 7. 实施节点

### R0：范围冻结与依赖清单（本文件）

- 固化保留、精简、移除范围。
- 固化商品分类和首页信息架构。
- 冻结当前 Git、数据库和 H5 部署基线。

### R1：商品与首页业务化

- 新建 3D 打印商品分类，移除演示分类和通用商城文案。
- 将“热门/新品/推荐”改为标签或运营集合。
- 调整首页入口、搜索筛选和空状态，突出定制打印、热门成品、秒杀和打印指南。
- 精简商品编辑，只展示成品/定制所需字段。
- 清理装修模板中已删除演示商品和旧商城分类的引用，生成可继续由管理员编辑的默认模板。

### R2：后台菜单与权限收敛

- 按第 3 章重组后台一级/二级菜单。
- 先禁用无关模块路由和权限，再移除独立页面。
- 建立超级管理员、客服、财务、库管四类角色最小权限。
- 工作台改为打印业务指标。

### R3：用户端页面与导航收敛

- 从首页、个人中心、商品详情和订单页面移除无关功能。
- 从 `pages.json` 删除无关页面注册，清理跳转、组件和 API 引用。
- 保留并统一 H5/App 共用业务页面和文案。

### R4：后端领域逻辑解耦

- 禁止优惠券、积分、会员、佣金、余额等逻辑参与新订单。
- 关闭无关 API、定时任务、消息和配置读取。
- 保持数据库兼容字段为零，先不激进删除共用字段。
- 清理确认无引用的独立控制器、服务和路由。

### R5：核心链路复核与节点 H 合并收尾

- 复核定制询价、成品、秒杀三条订单链互不串流。
- 完成异步文件校验、Web 根目录外存储、缺失站内信。
- 完成菜单 RBAC 和配置收口。
- 修复重构引入的问题后再交由用户构建 H5。

### R6：构建、正式测试与发布

- 用户使用 HBuilderX 构建 H5，部署后从干净数据开始正式测试。
- H5 通过后再构建 App。
- 最后开展自动化、安全、性能和发布收尾。

## 8. 删除操作的安全顺序

1. 创建 Git 节点和数据库备份。
2. 关闭入口、写入能力和定时任务。
3. 禁用旧路由/API，并检查核心代码是否仍引用。
4. 删除独立前端页面、组件和接口封装。
5. 完成构建与核心链路验证。
6. 删除确认无引用的后端代码。
7. 数据表和共用字段仅在最后单独评估，默认不作为本次首轮删除目标。

此顺序既能真正去除无关功能，也避免一次性物理删除导致 CRMEB 核心订单服务大面积报错。
